# Конспекты лекций

Мобильное приложение для записи лекций с распознаванием речи и ИИ-коррекцией текста.
Фото слайдов и видео встают в конспект в то место, где они были сняты.

```
project/
├── backend/      API на FastAPI: аккаунты, распознавание речи, коррекция текста
├── android/      Клиент для Android (Kotlin, Jetpack Compose)
├── mobile-rn/    Клиент для Android и iOS (React Native, Expo SDK 57)
└── .github/      CI: тесты, линтеры, сборки
```

Оба клиента одинаковы по функциям и работают с одним бэкендом.

## Как это работает

1. Пользователь входит в аккаунт, создаёт лекцию (тема и предмет помогают с терминами) и включает запись.
2. Звук пишется фрагментами по 3 минуты (моно, 16 кГц, AAC 32 кбит/с, около 0,7 МБ на фрагмент).
3. Готовый фрагмент отправляется на `POST /api/process`: сервер распознаёт речь, модель исправляет
   ошибки распознавания и пунктуацию, разбивает текст на абзацы. Вместе с фрагментом уходит конец
   уже готового текста, поэтому стыки получаются связными.
4. Фото слайда, снятое во время записи, закрывает текущий фрагмент в момент съёмки — снимок
   оказывается ровно между речью «до» и «после».
5. Текст можно править, переставлять блоки, повторно исправлять с помощью ИИ и откатывать к исходной расшифровке.
6. Видео добавляется с камеры, из галереи или ссылкой.
7. Конспект экспортируется в Markdown (текст, буфер обмена, файл `.md`).

Если сеть пропала, фрагменты ждут её и отправляются автоматически с нарастающей паузой между попытками.
Аудио при этом не теряется.

## Нейросети и свои ключи

По умолчанию сервер работает на своих ключах — рекомендуется **GigaChat** (коррекция текста) и
**SaluteSpeech** (распознавание речи) от Сбера: оба доступны из России и оплачиваются в рублях.

Пользователь может подключить в приложении собственный ключ (Настройки → «Свои ключи»), отдельно для
коррекции и для распознавания:

| Коррекция текста | Распознавание речи |
|---|---|
| GigaChat, ChatGPT (OpenAI), Claude (Anthropic), Gemini, DeepSeek, OpenRouter, Mistral, Groq, любой OpenAI-совместимый API | SaluteSpeech, Whisper (OpenAI), Whisper (Groq), любой OpenAI-совместимый `/audio/transcriptions` |

- Сервис определяется по формату ключа автоматически (его можно выбрать и вручную). Перед сохранением ключ
  проверяется на сервере (`POST /api/ai/check`).
- Ключ хранится только на телефоне в зашифрованном виде (Android Keystore / SecureStore) и отправляется
  вместе с запросом. Сервер его не сохраняет и не пишет в логи. Для GigaChat и SaluteSpeech в памяти
  сервера кэшируется только временный токен доступа (30 минут).
- На своём ключе суточные квоты сервера не тратятся; ограничение частоты запросов остаётся.
- Произвольный адрес API («Другой») проверяется: только HTTPS и только публичные адреса. Запросы во
  внутреннюю сеть сервера и к метаданным облака запрещены (защита от SSRF).
- При выходе из аккаунта ключи удаляются с телефона.
- Список сервисов приложение получает с сервера (`GET /api/ai/providers`). Чтобы добавить новый сервис
  с OpenAI-совместимым API, достаточно дописать его в `backend/app/providers/catalog.py`.

Особенности Сбера:
- Нужен «ключ авторизации» из личного кабинета developers.sber.ru и тип доступа (физлицо / ИП и юрлица).
- Сертификаты API подписаны НУЦ Минцифры. Они лежат в `backend/certs/russian_trusted_ca.pem` и
  используются **только** для запросов к Сберу, а не ко всем сайтам. Официальный источник —
  [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt). SHA-256 корневого сертификата:
  `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.
- SaluteSpeech не принимает AAC/M4A, поэтому сервер перекодирует фрагмент в WAV через ffmpeg
  (в Docker-образе ffmpeg уже есть). Используется асинхронное распознавание: синхронное ограничено одной минутой.

## Показ прототипа (Render + APK)

Сервер работает на Render, APK собирает GitHub Actions. На главной странице сервера лежат кнопка скачивания,
QR-код и инструкция по установке.

1. **Отправьте проект в GitHub** (`git push`). Файл `backend/certs/russian_trusted_ca.pem` должен попасть
   в репозиторий — для него сделано исключение в `.gitignore`.
2. **Поднимите сервер:** Render → New → Blueprint → выберите репозиторий. `render.yaml` создаст API, PostgreSQL
   и Key Value (Redis). Render попросит ввести:
   - `LLM_API_KEY` и `STT_API_KEY` — ключи авторизации GigaChat API и SaluteSpeech API из developers.sber.ru.
     Если ключей пока нет, смените `LLM_PROVIDER` и `STT_PROVIDER` на `none`: тогда на показе ключ вводится в
     приложении (Настройки → «Свои ключи»);
   - `DEMO_APK_URL`, `DEMO_APK_RN_URL` — оставьте пустыми, заполните после шага 3.

   Проверка: `https://<имя-сервиса>.onrender.com/api/ready` отвечает `{"status":"ok"}`, а на главной странице
   открывается страница прототипа.
3. **Соберите APK:** GitHub → Actions → «Сборка прототипа (APK)» → Run workflow, в поле адреса укажите
   `https://<имя-сервиса>.onrender.com`. Через 10–15 минут появится релиз `prototype-N` с файлами
   `lecture-notes.apk` (Kotlin) и `lecture-notes-rn.apk` (React Native).
4. **Подключите ссылки:** в Render → Environment задайте
   `DEMO_APK_URL=https://github.com/<владелец>/<репозиторий>/releases/latest/download/lecture-notes.apk`
   (и `DEMO_APK_RN_URL` — аналогично для `lecture-notes-rn.apk`). Ссылка `latest` всегда ведёт на свежую сборку.

Важно:
- Если репозиторий **приватный**, файлы релиза без входа в GitHub не скачать. Тогда загрузите APK из релиза на
  Яндекс Диск или Google Drive и укажите в `DEMO_APK_URL` прямую ссылку — либо сделайте репозиторий публичным.
- Бесплатный сервер Render засыпает после 15 минут без запросов и просыпается около минуты. Перед показом
  откройте страницу заранее или выберите тариф Starter. Бесплатная база удаляется через 30 дней.
- Сборки для показа подписаны debug-ключом. Перед установкой новой сборки удалите предыдущую.
- Render размещает сервер за рубежом (Франкфурт). Доступность API Сбера оттуда стоит проверить кнопкой
  «Проверить и сохранить» в приложении; при проблемах сервер можно перенести в российское облако (тот же Docker).

## Безопасность

**Сервер**
- Аккаунты по email и паролю. Пароли хранятся в виде хэша Argon2id.
- Сессии: access-токен JWT живёт 15 минут, refresh-токен 30 дней. Refresh-токены ротируются и хранятся
  в БД только как SHA-256. Если уже использованный токен приходит повторно (признак кражи),
  отзывается вся сессия.
- Ограничения частоты в Redis: вход (по IP и по email), регистрация (по IP), запросы к ИИ (по пользователю).
  Суточные квоты на объём аудио и текста защищают от перерасхода у платных провайдеров.
- Аудио проверяется по сигнатуре файла, а не по расширению. Размер запроса ограничен ещё до разбора
  multipart. Длина текста тоже ограничена.
- Текст лекции передаётся модели как данные, а не как инструкции: служебные теги из него вырезаются.
  Это защита от prompt injection.
- Ошибки провайдеров и необработанные исключения не раскрываются клиенту. В ответ на ошибку валидации
  присланные значения (например, пароль) не возвращаются.
- Логи — JSON с request-id, без содержимого лекций и без токенов.
- Заголовки безопасности (HSTS, CSP, nosniff, no-store), проверка `Host`. CORS по умолчанию выключен.
  В боевом режиме Swagger отключён.
- Боевой режим (`ENVIRONMENT=production`) не запустится со слабым `JWT_SECRET`, SQLite, без Redis,
  с заглушками провайдеров или с `CORS_ORIGINS=*`.
- Контейнер: отдельный пользователь без root, файловая система только для чтения, `cap_drop: ALL`,
  `no-new-privileges`. PostgreSQL и Redis доступны только во внутренней сети, наружу открыт лишь Caddy
  с автоматическим HTTPS.
- Конспекты, фото и аудио на сервере не хранятся. Сервер видит аудиофрагмент только на время обработки.
  Есть удаление аккаунта (`DELETE /api/auth/me`).

**Android (Kotlin)**
- Токены зашифрованы AES-256-GCM ключом из Android Keystore.
- Release: только HTTPS, доверие только системным сертификатам. HTTP к локальному серверу разрешён
  лишь в debug-сборке (`src/debug/res/xml/network_security_config.xml`).
- Адрес сервера зашит в release-сборку. Менять его в настройках можно только в debug.
- `allowBackup=false` и запрет переноса данных: конспекты и токены не попадают в облачные бэкапы.
- R8 (минификация и обфускация) и удаление неиспользуемых ресурсов. В release нет логов `Log.d/i/v`
  и сетевого лога.
- Файлы лежат во внутренней памяти приложения и отдаются другим приложениям только через FileProvider.
- Фото пересохраняются без EXIF, то есть без геолокации.

**React Native**
- Токены в `expo-secure-store` (Keystore/Keychain, только это устройство).
- Окружение задаётся при сборке: в `APP_ENV=production` только HTTPS, адрес сервера из `API_URL`,
  `allowBackup=false`, R8 и сжатие ресурсов.

## Оптимизация

- Запись мелкими фрагментами: текст появляется по ходу лекции, запросы к провайдеру короткие и укладываются в лимиты.
- Android: очередь отправки на WorkManager — переживает закрытие приложения и перезагрузку телефона,
  ждёт сети. RN: последовательная очередь с ожиданием сети через NetInfo.
- Фото сжимаются до 2560 px / JPEG 85% (обычно с 4–12 МБ до 0,5–1 МБ).
- Ограниченный кэш картинок (Coil), превью видео по кадру.
- Сервер: один HTTP-клиент с пулом соединений, ограничение одновременных запросов к провайдерам,
  повторы с экспоненциальной задержкой при 429/5xx, пул соединений к PostgreSQL, gzip.

## 1. Бэкенд

### Локально

Нужен Python 3.12 или новее.

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate             # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env             # Linux/macOS: cp .env.example .env
uvicorn app.main:build --factory --reload
pytest
```

В режиме `development` используются SQLite (`dev.db`, таблицы создаются автоматически) и заглушки
провайдеров: всё приложение можно проверить без ключей API. Документация API: `http://localhost:8000/docs`.

### Сервер (Docker Compose)

```bash
cd backend
cp .env.example .env
# Заполнить: ENVIRONMENT=production, JWT_SECRET, DOMAIN, ALLOWED_HOSTS, POSTGRES_PASSWORD, REDIS_PASSWORD,
# STT_*/LLM_* — провайдеры и ключи. Секрет: python -c "import secrets; print(secrets.token_urlsafe(48))"
docker compose up -d --build
```

Поднимутся API, PostgreSQL, Redis и Caddy (HTTPS-сертификат выпускается автоматически для `DOMAIN`).
Миграции применяются отдельным сервисом `migrate` перед стартом API.

Служебные команды (внутри контейнера `api`):

```bash
python -m app.cli create-user user@example.com   # если регистрация закрыта (REGISTRATION_ENABLED=false)
python -m app.cli deactivate-user user@example.com
python -m app.cli purge                          # старая статистика и просроченные токены (раз в сутки по cron)
```

### Нейросети сервера

Пример для Сбера в `.env`:

```env
LLM_PROVIDER=gigachat
LLM_API_KEY=<ключ авторизации GigaChat API>
LLM_MODEL=GigaChat-2-Pro          # по умолчанию GigaChat-2
LLM_SCOPE=GIGACHAT_API_PERS       # или GIGACHAT_API_B2B / GIGACHAT_API_CORP
STT_PROVIDER=salutespeech
STT_API_KEY=<ключ авторизации SaluteSpeech API>
STT_SCOPE=SALUTE_SPEECH_PERS
```

`LLM_PROVIDER` / `STT_PROVIDER` принимают любой id из каталога, а также `mock` (заглушка для разработки)
и `none` (ключа сервера нет — пользователи работают только со своими ключами).
`ALLOW_USER_KEYS=false` запрещает свои ключи, `ALLOW_CUSTOM_BASE_URL=false` — произвольные адреса API.

API OpenAI, Anthropic и Google недоступны напрямую с российских IP. Для них сервер должен стоять за рубежом;
GigaChat и SaluteSpeech, наоборот, удобнее вызывать с сервера в России.

### API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login` | Регистрация / вход, возвращает пару токенов |
| POST | `/api/auth/refresh` | Обновление пары токенов (ротация) |
| POST | `/api/auth/logout` | Отзыв сессии |
| GET / DELETE | `/api/auth/me` | Профиль / удаление аккаунта (с паролем) |
| POST | `/api/process` | Аудиофрагмент → текст → коррекция |
| POST | `/api/transcribe`, `/api/correct` | Только распознавание / только коррекция |
| GET | `/api/usage` | Расход за сутки и лимиты |
| GET | `/api/ai/providers` | Каталог нейросетей и что настроено на сервере |
| POST | `/api/ai/check` | Проверка ключа пользователя (ключ не сохраняется) |
| GET | `/api/health`, `/api/ready` | Проверка процесса / готовности БД и Redis |

## 2. Android (Kotlin)

Откройте папку `android/` в Android Studio (JDK 17) и запустите конфигурацию `app` (debug).
Debug-сборка ходит на `http://10.0.2.2:8000` (локальный сервер из эмулятора). Адрес можно сменить в настройках.

Release-сборка:

```bash
cd android
./gradlew assembleRelease \
  -PlectureApiUrl=https://api.your-domain.ru/ \
  -PlectureKeystore=/path/release.jks -PlectureKeystorePassword=... \
  -PlectureKeyAlias=... -PlectureKeyPassword=...
```

Те же параметры можно передать переменными окружения `LECTURE_API_URL`, `LECTURE_KEYSTORE` и т.д.
Ключ подписи в репозиторий не добавляется.

Стек: Compose (Material 3), Room, DataStore, WorkManager, Retrofit + OkHttp + kotlinx.serialization,
Coil, Media3. minSdk 26, targetSdk 34.

## 3. React Native (Expo)

```bash
cd mobile-rn
npm install
npx expo run:android                 # dev-сборка, сервер http://10.0.2.2:8000
npm run lint && npx tsc --noEmit
```

Нужна development build, Expo Go не подойдёт: фоновой записи звука нужна нативная настройка.
Боевая сборка в облаке: укажите адрес сервера в `eas.json` (`API_URL`) и выполните
`npx eas-cli@latest build --profile production`.

## Проверка

- Бэкенд: 65 тестов — аутентификация, ротация и отзыв токенов, лимиты, квоты, валидация аудио,
  заголовки безопасности, все протоколы провайдеров (OpenAI-совместимый, Anthropic, GigaChat с кэшем
  и обновлением токена, SaluteSpeech с перекодированием), определение сервиса по ключу, защита от SSRF.
  Запросы к провайдерам в тестах подменяются. Прогоняются на SQLite и на PostgreSQL + Redis.
  Миграции проверяются вверх и вниз. `ruff` без замечаний.
- Живые запросы к GigaChat и SaluteSpeech с настоящим ключом не выполнялись: из среды разработки API
  Сбера недоступен. Первый прогон стоит сделать с реальным ключом через «Проверить и сохранить».
- React Native: `tsc` и `eslint` без ошибок, production-бандл собирается.
- Android: синтаксис проверен компилятором Kotlin. Полную сборку (debug, release с R8, lint)
  выполняет CI в GitHub Actions — `.github/workflows/ci.yml`.
